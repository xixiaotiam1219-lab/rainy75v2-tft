# 验证范围

公开源码包使用三类检查：

1. **主机协议测试**：帧长度与校验、旧版 ACK 兼容、错误目标拒绝、烧录全部字节及尾块覆盖、校时读回、旧固件拒绝、素材覆盖确认。
2. **资源与构建检查**：三套原创 GIF 可逐帧解码，点阵边界与居中，原厂输入 SHA、补丁指令、原厂前缀与未声明区域保持不变，新增 ROM/RAM 边界。
3. **浏览器模拟**：离线像素编辑、导出、USB mock 的直接校时与旧版拒绝，桌面与移动布局。它不会访问真实 HID。

可选浏览器测试需另行安装 Playwright，不是运行网页的依赖：

```sh
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install chromium
node tests/browser.smoke.mjs
```

可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定本机 Chromium / Edge。测试会生成工作台截图 `assets/studio.png`，数据与验证结果留在被忽略的 `build/`。

开发阶段使用的已知旧工具链构建主控 7.1 时，可复现镜像 SHA：

```text
c9e26045df8dcabb37de6b06ed6c94fbf036edce32b371554878b4532beed1e9
```

该哈希仅是指定源码、输入、参数和编译器的复现参照。其他编译器版本可能产生不同代码；哈希一致也不证明硬件行为正确。这里不分发对应完整镜像。

**未完成的实机验证**：主控 7.1 校时标记修正、公开默认机器人素材、重新定制构建的显示、覆盖全部休眠与切换模式、完全关电后的使用体验，以及完整的输入延迟、功耗和稳定性测量。当前 README 必须继续标注 alpha 与这些限制。

## 0.2 新增歌词扩展的检查

基础版仍单独构建和使用；歌词扩展增加下列自动检查：

- `npm test`：当前31项，覆盖原协议回归、歌词版本/时长筛选、重复候选、重试、异步切歌保护、缓存键、NFC字形编码、USB描述符与报告适配、重连模式、字库双CRC、扩展镜像全字节/尾部校验、芯片预检拒绝、离线控制台保存偏移与中文分块请求；新增20/40切换及旧固件兼容、字库定点替换的前置校验、排队、失败、超时与恢复。所有设备与网络请求均用模拟对象，不访问真实HID或播放器。
- Python资源/字库测试：当前5项，覆盖三套原创GIF的完整帧与标记像素、图标边界/居中、字库格式、索引、CRC与fallback。
- `tests/lyrics-console.smoke.mjs`：真实无头浏览器访问离线演示后台，测试按钮/数值偏移、归零、两页切换和桌面/移动布局；不注册快捷键或读取媒体。

```sh
npm test
python -m unittest discover -s tests -p "test_*.py"
node tests/lyrics-console.smoke.mjs
```

最后一条需按上文安装可选Playwright及浏览器。README的歌词控制台图片来自这份离线演示。

## 本地ARM指令模型

有合法原厂输入、本地字库与Clang时先完成 [歌词构建](lyrics.md)，再运行：

```sh
python -m pip install -r requirements-model.txt
python tools/test_lyrics_model.py
```

可加 `--build build/ips-lyrics` 选择构建目录，`--preview build/player-preview.png` 生成模型绘制的示例画面。脚本执行本机构建的真实Cortex-M4机器码，模拟FatFs、分配器、原厂回调、LCD DMA和UART，验证只读容量查询、原生Shift与保留按键、96字独立标题滚动、预载缓存复用、每轮四次读取上限、分配失败所有权、最大字段、DMA不可变、返回按键页与挂起资源释放。

此模型不是完整原厂启动、硬件供电、物理输入延迟、真实LCD扫描或恢复能力的证明。公开代码已在本地用匹配原厂输入重新构建并通过模型；源码化后的默认机器人配置仍需使用者实际查看屏幕。

0.2.0-alpha.2新增逐像素验证：同一字库同时绘制20px标题和40px当前句，切换布局不读字形、不增加分配；固定FONT替换在未暂停时拒绝，在UART只排队、DMA忙时不执行；旧头部不匹配时保留文件，句柄关闭后只unlink固定文件，恢复时取消未执行的队列。`--preview assets/player-pink.png`同时导出大字图及`player-pink-20.png`小字图，均为模型输出。

## 开发设备观察与公开版的区别

同源歌词逻辑在一台1024KiB AT32F435/4MiB外置Flash设备上有安装、全字节烧录核对和QQ同步记录。一次30秒观察中7次提交约152–432ms，中位245ms；这是电脑发送到设备提交应答的耗时，**不是按键输入延迟，也不是可保证的音画误差**。不同曲目、字长、GUI负载与环境会改变结果。

网易云新Elog适配尚未做当前客户端的实机复核。纯音乐、Live/Remix/不同剪辑、接口限流和歌词本身的时间戳问题仍可能导致缺词或错位。不要把QQ个别曲目成功写成所有来源、版本和连接方式都已验证。

同源20/40布局和FONT专用替换在这台开发设备上已完成安装、整镜像烧录校验、旧字体释放、新字体提交与ready/布局读回，QQ后台恢复同步。素材清单中的其他条目大小保持一致；这不等于读回其全部内容。公开默认字体/主题以及新增排队取消分支仍以公开构建和模型检查为证据，不能标成全批次实机验证。

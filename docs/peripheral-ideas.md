# 从一块键盘屏幕出发

本项目的功能集中在 Rainy75 V2，但过程中得到的方法也能用于 USB 小屏、宏键盘、桌面提示牌和其他带显示的外设。下面是思路，不是这些外设的成品驱动。

## 素材和状态分开

频繁上传 GIF 或整帧图片会重复触发文件系统、下载界面和解码初始化。更适合小外设的一种组织方式是：动画素材存一次，状态发生变化时只发送必要字段；设备用同一帧合成文字、图标和动画。

一个 320×172 RGB565 完整帧需要 110080 字节，而一个时钟快照只需要几字节。实际方案仍需计入串口/USB 封装、文件系统、解码开销与屏幕传输，不能仅按标称串口波特率承诺帧率。

## 先找原生事件

键盘本来就知道按键、电量和连接方式，优先复用这些通知，可减少对电脑全局输入监听、后台窗口和每秒轮询的依赖。迁移到旋钮或宏键盘时也可先寻找旋转、层切换、音量或电池事件。

要实际确认通知的语义：按下还是松开、键码还是字符、Shift 是位掩码还是布尔值、哪些模式重启设备。字段看起来像 HID，不代表它就按 HID 标准编码。

## 给每份数据一个所有者

背景 GIF、动态时间和按键区域若由不同任务随意写入同一缓冲区，可能互相覆盖。明确哪个任务合成、哪个任务启动 DMA，以及缓冲区何时可再次修改。

接收层只做有界解析；绘图、文件写入和较慢操作放在合适的任务中。忙时返回忙状态、保留最新状态或有限重试，避免无限等待、堆积旧数据和在中断里阻塞传输。

## 时间从哪里来

“有 RTC 外设”不等于“断电后仍然走时”。需要核对振荡源、供电域、后备电源、启动时是否重置、模式切换与休眠是否丢失状态。

保存“校准时刻”并不能自动知道停电期间经过了多久；RAM 标记也不一定跨 bootloader、复位或低功耗模式保留。持久记录需要明确格式、校验、提交顺序和失效规则。完全失去计时源时，应标为未知，再从可信来源校准。

## 几个可尝试的方向

- **AI 状态牌**：电脑端把任务状态转换为“空闲 / 思考 / 执行 / 完成”，外设只接收枚举和简短文字；不要把云 API 密钥放入设备。
- **桌面番茄钟**：在有可靠独立计时源的设备上，本地计时并播放状态动画；先验证断电、睡眠和误差。
- **媒体提示屏**：通过播放器或系统支持的接口取得曲名、进度，再发轻量数据。歌词需要额外的来源、同步和授权工作，本仓库未实现。
- **宏键盘状态面板**：显示当前层、最近操作或电池；优先使用固件原生事件，避免为了显示而改变输入路径。
- **电脑监控小屏**：桌面程序只发送最新温度、占用或网络状态；明确传感器来源和采样间隔，不无限排队旧画面。

## 让 AI 参与，但留下证据

AI 适合读公开 SDK、整理协议、写生成器、做图标预览、补边界测试和文档。每一步都保留“依据是什么”“在哪个版本上验证”“哪些还没测”的记录，再决定是否上真实硬件。

本仓库的固定地址与补丁只对已列明原厂输入有效。迁移时应重新建立硬件和软件证据，不应把这里的地址当作同系列设备的通用接口。
